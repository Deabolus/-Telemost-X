# Официальные интеграции Яндекс Телемоста

**Проверено:** 2026-11-13  
**Тип проверки:** анализ публичной документации и публичного GitHub-поиска.  
**Живые запросы к Telemost/Xiva не отправлялись.**

## Краткий вывод

У Яндекса есть официальные способы интеграции с Телемостом, но они не
подтверждают возможность построить самостоятельный клиент чатов поверх Xiva:

1. **Публичный REST API Телемоста** документирован для встреч, трансляций,
   соорганизаторов и настроек организации. Для него регистрируют собственное
   OAuth-приложение с правами из каталога API. Документация ограничивает API
   пользователями Яндекс 360 для бизнеса с аккаунтами на домене организации.
   В каталоге нет общих методов чтения истории чатов или отправки сообщений.
2. **Официальный MCP-сервер Телемоста** опубликован как предварительная версия
   для внешних ИИ-агентов. Он умеет находить чаты и читать сообщения, но
   операции с чатами/сообщениями ограничены чтением. Это MCP-интеграция, а не
   Android SDK или документированный прямой Xiva-контракт.
3. **SDK или разрешённый прямой Xiva/WebSocket-протокол** в просмотренных
   официальных каталогах не обнаружен. Отдельная публичная программа
   партнёрской регистрации для сторонних клиентов не установлена. Нельзя
   делать вывод, что закрытых партнёрских условий не существует.

Следовательно, прежний вывод «официального API Телемоста не найден» нужно
уточнить: официальный API есть, но публично описанные возможности не
подтверждают полноценный независимый мессенджер-клиент. Для создания/чтения
встреч есть REST API, для чтения чат-контента — MCP preview; для отправки
чат-сообщений и Xiva-сокета поддерживаемый сторонний контракт не найден.

## 1. REST API

Официальная [документация API Телемоста](https://yandex.com/dev/telemost/doc/ru/)
описывает REST API для видеовстреч, трансляций, списка соорганизаторов и
настроек по умолчанию. Индекс документации перечисляет только эти разделы:
[индекс API](https://yandex.com/dev/telemost/doc/ru/llms.txt).

В [разделе доступа](https://yandex.com/dev/telemost/doc/ru/access.md) указано:

- приложение создаётся в Yandex OAuth по типу **API access**;
- в приложении выбираются права, используемые Telemost API;
- приложение получает OAuth-токен, который пользователь передаёт API;
- доступ к API Телемоста доступен пользователям Яндекс 360 для бизнеса,
  чьи аккаунты находятся на домене организации.

### Scopes, перечисленные в документации

| Scope | Заявленное назначение |
|---|---|
| `telemost-api:conferences.create` | Создание встреч и трансляций |
| `telemost-api:conferences.read` | Просмотр данных встреч и трансляций |
| `telemost-api:conferences.update` | Изменение данных встреч и трансляций |
| `telemost-api:organization_settings.read` | Просмотр общих настроек встреч организации |
| `telemost-api:organization_settings.update` | Изменение общих настроек встреч организации |

Для списка соорганизаторов документация повторно указывает
`telemost-api:conferences.read` и `telemost-api:conferences.update`.
Индекс REST API не перечисляет `list_chats`, `history`, `list_messages` или
`send_message` операции. Некоторые операции с встречами могут упоминать
создаваемый рядом чат, но это не документирует чат API.

Страница регистрации API-приложений Yandex ID объясняет общий механизм выбора
сервисных прав: [регистрация приложения для API access](https://yandex.com/dev/id/doc/ru/register-api).
Это разрешает зарегистрировать приложение для документированных scopes,
но само по себе не даёт прав, отсутствующих в каталоге Telemost API.

## 2. MCP-сервер Телемоста

В официальной документации опубликован
[MCP-сервер Телемоста](https://yandex.ru/dev/yandex-360/mcp/ru/telemost).
Документ называет его **предварительной версией** и описывает подключение
внешнего ИИ-инструмента с OAuth-разрешением пользователя.

Доступные MCP-инструменты включают поиск/просмотр чатов, участников, сообщений
и тредов. Документация прямо ограничивает чат-операции чтением: нельзя
создавать, изменять или удалять чаты; отправлять, изменять или удалять
сообщения; менять состав участников, роли или состояние прочтения. Управление
встречами через MCP имеет отдельные инструменты и подтверждения пользователя.

Документация не публикует в текстовом виде точные идентификаторы scopes,
запрашиваемых преднастроенным OAuth-клиентом MCP; она предлагает пользователю
проверить права в окне авторизации. Поэтому scope MCP не приравнивается здесь
к scopes REST API и не реконструируется по внутренним данным приложения.
Точные условия доступности для типов аккаунтов требуют проверки по
официальному окну согласия и/или документации поддержки.

MCP — реальная официальная интеграция для внешних инструментов, но не
публичный Android SDK и не универсальный API для самостоятельного клиента.
В [правилах безопасности MCP](https://yandex.ru/dev/yandex-360/mcp/ru/security.md)
Яндекс также указывает, что внешний инструмент выбирает пользователь, Яндекс
не контролирует его дальнейшее хранение/использование полученных данных, и
запрещает обход ограничений, массовый сбор данных и доступ без полномочий.

## 3. SDK и партнёрская/корпоративная программа

- В индексе официального Telemost REST API перечислены REST-методы, но не
  клиентский SDK для чатов или Xiva.
- В документации Yandex ID доступен общий мобильный SDK для OAuth-входа, но
  наличие SDK авторизации не означает наличие Telemost messaging API.
- Документация REST API задаёт публичный корпоративный путь через Yandex
  OAuth app access и business-аккаунт на домене организации. Она не описывает
  отдельный этап согласования партнёрского договора для этих перечисленных
  REST scopes.
- MCP — отдельный публично документированный путь для внешнего MCP-клиента,
  в предварительной версии; его нельзя считать доказательством поддержки
  произвольных клиентов или прямого Xiva.
- Поиск репозиториев GitHub в официальной организации `yandex` по слову
  `telemost` не вернул SDK/клиентский репозиторий. Это ограниченный поиск, а
  не доказательство отсутствия закрытых или опубликованных вне этой
  организации SDK.

Отдельная официальная партнёрская программа для разработки сторонних
Telemost/Xiva-клиентов в проверенных источниках не обнаружена. Это
**неизвестное**, а не подтверждённое отсутствие такой программы.

## 4. Влияние на network-gate

| Возможность | Поддерживаемый путь по найденной документации | Статус для эксперимента |
|---|---|---|
| Управление встречами/трансляциями | REST API + перечисленные `telemost-api:*` scopes; бизнес-домен | Документировано, но тест не выполнялся |
| Чтение доступных чатов/сообщений | MCP preview, от имени пользователя, read-only | Документировано для MCP; не эквивалентно native Android API |
| Отправка чат-сообщений | Не найдено в REST каталоге; MCP явно не поддерживает | Блокер для клиента с отправкой |
| Прямое подключение к Xiva/WebSocket | Официальный SDK/контракт не найден | Блокер; внутренний протокол не используется |

Никакие токены не получались, scopes не запрашивались, MCP/REST endpoints не
вызывались. Серверные ответы отсутствуют. Следующий разрешённый шаг зависит от
цели: если устраивает только чтение в рамках внешнего AI-инструмента, отдельно
оценить MCP preview и его условия; если нужен самостоятельный Android
мессенджер с отправкой, запросить у Яндекса документированный API/SDK и
разрешённые права для этой операции до сетевого теста.
