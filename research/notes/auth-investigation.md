# Telemost X — исследование авторизации

Дата: 2026-11-12

## Подтверждено

1. Оригинальное приложение использует
   `com.yandex.messaging.ui.auth.ProxyPassportActivity`.

2. Найдены вызовы Activity:
   - `id1.java` — действие LOGIN, requestCode 2571.
   - `cyd.java` — действие LOGIN, requestCode 2567.
   - `sfj.java` — действие BIND_PHONE, requestCode 2571.

3. `c8g.java`, case 16:
   - создаёт `p0j` через `iu6`;
   - для LOGIN вызывает `p0j.b("action_login")`;
   - для BIND_PHONE вызывает `p0j.a(...)`;
   - запускает полученный Intent через startActivityForResult.

4. `p0j.java` — обёртка над Passport:
   - зависит от `gj1` (passportWrapper);
   - использует `nb1` (authUid);
   - формирует Intent через `gj1.a(...)`.

5. `d1j.java` — менеджер запросов Passport:
   - запрашивает токен через `gj1.d(...)`;
   - затем запускает запрос пользователя;
   - поддерживает отмену запросов.

## Что пока не доказано

- Можно ли использовать ProxyPassportActivity вне оригинального приложения.
- Какие зависимости и компоненты Passport обязательны.
- Как именно результат входа передаётся основному приложению.
- Как получить пользовательскую сессию для нашего клиента.

## Не путать

- `q78.java` — перегруженный класс с несвязанными функциями.
  Найденная строка oauth_access_token сама по себе не доказывает
  участие класса в авторизации пользователя.

- `t1i.java` — показанный фрагмент сохраняет Firebase
  PersistedInstallation (Fid, AuthToken, RefreshToken).
  Не считать его хранилищем пользовательской сессии Яндекса.

- `v4s.java` — формирует заголовок Authorization: OAuth,
  но назначение конкретного запроса пока не установлено.
